## A1. Inhibitor panel (`BD/select_inhibitors.py`)

**Features** (`communication_features`, l.29–52), computed from isolated profiles:

| Feature | Definition |
|---|---|
| comm_frac | T_MPI / T_app |
| log1p(message rate) | log1p(msgs / T_app) |
| log1p(byte rate) | log1p(bytes / T_app) |
| log1p(mean message size) | log1p(bytes / msgs) |

Here T_app = T_MPI / comm_frac.

**Scaler and distance:**
- The scaler is fit on the **target applications only**, never on the inhibitor grid (l.161–169). It uses the
  population SD (`np.std`, ddof 0).
- A feature that is constant across the targets is dropped from the distance.
- Distance: d²(a, j) = mean over active features f of ((x_af − z_jf) / s_f)². This is an RMS standardized distance.

**Eligibility** (l.155–158): an inhibitor is a candidate only if it has a valid forward (application-slowdown) response
for **every** target application. Auxiliary labels and response magnitude play no role. App-App data is never loaded.

**Objective** (`coverage_score`, l.55–60). With n_a(S) = min over j in S of d²(a, j):

  F(S) = (1 − τ) · mean_a n_a(S) + τ · max_a n_a(S),  with τ = 0.5,  |S| ≤ B = 10.

**Optimization** (`select_panel`, l.63–130):
1. If the union of each application's nearest eligible inhibitor fits the budget, take that union. It achieves the
   pointwise lower bound, so it is globally optimal.
2. Otherwise, run greedy forward selection followed by one-swap local search.
3. Finally, remove redundant inhibitors (the budget is a cap, not a quota).

**Why 9, not 10:** the nearest-inhibitor union has 9 distinct members because Kripke and LAMMPS share their nearest
inhibitor, (2.5 MB, 6e5 µs, 0.0022). The status is "global_optimum_pointwise_lower_bound", so no tenth inhibitor can
lower the objective, and none is added.

## A2. Models (`BD/model.py`, `BD/training.py`, `BD/inference.py`; the 1W pipelines contain the same legacy classes)

**Notation:**
- x = isolated-profile input, base feature set: [log1p T_MPI, comm_frac, log1p msgs, log1p bytes], standardized by a
  fold-local scaler.
- E = shared encoder: Linear(4→h) → ReLU → Linear(h→e) → ReLU.
- y = log slowdown ≥ 0.
- Prediction: ŝ = exp(max(0, R̂)). That is, the latent log response is floored at 0 (`observe_log_slowdown`).

**Censored Huber losses** (training.py l.89–120). Huber δ = 1.0 everywhere.

*Absolute loss.* The residual is:

| Observation | Residual |
|---|---|
| exact (y > 0) | r = R̂ − y |
| floor (y = 0) | r = max(0, R̂) |

The loss is Huber_δ=1(r), so a floor observation is penalized only when the model predicts above the floor.

*Delta loss* on a pair (anchor J, query K) with predicted Δ̂ = R̂(A,K) − R̂(A,J). The residual depends on which
observations are exact:

| Case | Residual |
|---|---|
| both exact | Δ̂ − (y_K − y_J) |
| query at floor | max(0, Δ̂ + y_J) |
| anchor at floor | max(0, y_K − Δ̂) |
| both at floor | 0 |

In the legacy loss, both-floor pairs contribute 0 but still count in the mean. In the joint model's
`identified_delta_huber_loss`, both-floor pairs are excluded from the mean.

**Variants:**

1. **Absolute response** (`AbsoluteResponseModel`, model.py l.93; same architecture as the low-rank potential):
   - R(V,X) = h(E(x_X)) + ⟨u(E(x_V)), v(E(x_X))⟩.
   - h is an MLP e→h→1. u and v are linear e→rank.
   - There is **no victim-level term b(e_V)**.
   - Trained on App-Inhibitor rows with the censored absolute loss (`train_absolute`).
2. **Low-rank delta / replacement potential** (`LowRankPotential`, l.23):
   - Same R as the absolute model, but trained only on within-victim differences R(A,K) − R(A,J). The pairs come from
     the episode sampler: a uniform victim, then two distinct inhibitors (training.py l.37–86).
   - Inference uses anchors (inference.py l.122–185): over the victim's **uncensored** panel anchors J,
     compute residuals ρ_J = y_J − R̂(V,J), then log ŝ(V,X) = max(0, R̂(V,X) + agg(ρ)).
   - Aggregations (`aggregate_residuals`, l.79–119):
     - uniform: mean of ρ;
     - median: median of ρ;
     - kernel: softmax(−dist²/T)-weighted mean, with dist = Euclidean distance in scaled profile space and
       T ∈ {0.1, 0.3, 1, 3, 10};
     - OOD-kernel: α·kernel + (1−α)·fallback (median or uniform). α = 1 when the nearest anchor is within the q-quantile
       (q ∈ {0.9, 0.95, 0.99}) of the validation nearest-neighbour distances; otherwise
       α = exp(−(d − thr)/median_width).
   - The aggregation is chosen by the **grouped one-standard-error rule**, in complexity order
     uniform < median < kernel < OOD-kernel (1W/pipeline.py l.575–608).
   - Selected (primary) aggregation per pipeline:

     | Pipeline | Selected aggregation |
     |---|---|
     | One-way MPI (current) | uniform |
     | One-way MPI (legacy) | uniform |
     | One-way total time | OOD-kernel |
     | Bidirectional (both targets) | uniform (the artifact's choice) |

   - A victim with **no uncensored anchor cannot be predicted**. This is the one-way coverage failure.
3. **Generic potential** (`GenericPotential`, l.59):
   - R(V,X) = MLP([e_V, e_X, e_V⊙e_X]): 3e→h→1, with no low-rank factorization. Trained with the same delta loss and
     anchor inference.
   - Its class defaults are h = 16, e = 8. The runs passed the default ModelConfig (h = 8, e = 4), so in the reported
     runs it has the **same width** as the others (artifact recipes: hidden 8, embedding 4). The difference is
     structural (an unfactorized head), not a larger head.
4. **Joint response** (`JointResponseModel`, l.123):
   - R(V,X) = b(e_V) + h(e_X) + ⟨u(e_V), v(e_X)⟩, where b and h are MLPs e→h→1.
   - Shared encoder 4→8→4 (ReLU), rank 2.
   - Loss: L = 1.0·L_abs + 1.0·L_Δ + 0.1·L_aux (pipeline.py `RunConfig` l.200–202).
     - L_abs is the masked censored absolute Huber.
     - L_Δ is averaged over identified delta constraints only.
     - L_aux = 0 for joint_profile.
   - Deltas are differences of R, so identity, antisymmetry and path consistency hold exactly.
5. **Floor-aware calibration** (`fit_floor_aware_offset`, inference.py l.283; `CalibrationConfig` l.214):
   - ĉ = argmin_c Σ_J w_J ℓ_J(c) + (λ/2)c².
   - ℓ_J is Huber_δ=1 of (R̂_J + c − y_J) for exact anchors and of max(0, R̂_J + c) for floor anchors.
   - w gives equal total weight per inhibitor configuration and is normalized to sum to 1.
   - Solved by bisecting the monotone derivative (tolerance 1e-10, 200 iterations).
   - λ ∈ {0.1, 1, 10} is selected by App-Inhibitor crossed CV. Selected values: λ = 1 for all joint variants except
     the forward-only ablation (λ = 10), in both targets.
   - Prediction: max(0, R̂ + ĉ). Empty support falls back to c = 0.
   - All-floor support is valid, so no fold is skipped.
   - Applies to joint-family variants only ("_calibrated"; "_direct" = no offset).
6. **Bidirectional auxiliary supervision** (bidirectional_profile and _context):
   - **Targets.** Three rate-change targets, all of the form log(rate_iso) − log(rate_co), positive = degradation,
     never clipped:
     - bw_wall = bytes / T_app;
     - bw_mpi = bytes / T_MPI;
     - msg_wall = msgs / T_app.
   - Each target is defined for **both endpoints** of an App-Inhibitor run: the app ("incoming") and the inhibitor
     ("outgoing"). The inhibitor-endpoint labels are the "reverse direction": the inhibitor's rate change under the
     application trains the application's aggressor representation. No inhibitor slowdown labels are invented.
   - **Head.** MLP on [e_V, e_X, u(e_V), v(e_X), u⊙v]: (2e + 3·rank) → 8 → 3, evaluated in both orders.
   - **Loss.** Huber on residual / σ_t with σ_t = max(std_train(d_t), 0.1), averaged within each task and then across
     available tasks. Weight 0.1.
   - **Wall-clock-only ablation:** {bw_wall, msg_wall} only.
   - Caveat: for applications, bytes and messages don't change under co-scheduling. So app bw_mpi equals the raw log
     MPI ratio, and bw_wall equals msg_wall (README).
7. **Response fingerprints** (bidirectional_context; `SupportSetEncoder` l.100, `JointResponseModel.embed`):
   - One token per (application, inhibitor config). It contains:
     - the inhibitor's scaled isolated profile;
     - the app's mean log slowdown and floor fraction on that config;
     - training-scaled mean rate changes for the app endpoint (incoming) and the inhibitor endpoint (outgoing; dropped in
       the forward-only ablation);
     - availability flags.
   - Pooling: masked mean over token → 8 → 4. Then MLP([pooled, 1_support, log(1+n)]) → e is **added** to e_V. Empty
     support adds exactly 0, and inhibitors always have empty context.
   - Training episodes: support S and 2 queries with S ∩ Q = ∅, P(|S| = 0) = 0.25, |S| ≤ min(n−2, 7).
   - Calibration is cross-fitted (up to 3 views; view latents averaged).

## A3. Protocol (`run_experiments.py`, profile "standard")

**Shared settings:**
- Optimizer: AdamW.
- Epochs: max 80, early-stopping patience 10, 4 batches of 128 episodes per epoch.
- Seeds: CV seeds 0–4 and final seeds 0–4.
- Bootstrap: 1,000 draws, seed 923.
- Device: CPU. The artifact runs used `OMP_NUM_THREADS=1` and 12–16 workers.

**Crossed CV:**
- Panel inhibitors are clustered into **4 blocks** by K-means on their standardized base profiles (seed 1701,
  n_init 20; BD/pipeline.py l.366–375).
- Each fold holds out application A* × block B*, giving 10 × 4 = 40 groups.
- Training excludes every label of A* and every run in B*, including reverse labels.
- Scalers are fold-local. A*'s rows outside B* serve as support/anchors, and its rows in B* are the queries.
- Validation metric: grouped slowdown log MAE, averaged query → (victim, block, seed) → seeds → groups.
- If the panel has fewer than 4 inhibitors, K-means cannot run ("inhibitor_blocks exceeds the number of panel
  inhibitors"). That is the size 2–3 failure.

**Selection:**
- **One-way runner** (1W/run_experiments.py l.50, 138–145, 570–590). Three sequential crossed-CV stages, each freezing
  the previous winner, **for the low-rank delta only**:
  1. architecture: feature set {base, augmented} × rank {1, 2, 4} (6 candidates);
  2. optimizer: lr {3e-4, 1e-3, 3e-3} × weight decay {0, 1e-4, 1e-3} (9 candidates);
  3. capacity: (hidden, embedding) ∈ {(4,2), (8,4), (16,8)} (3 candidates).

  Generic and absolute use the fixed default (base features, hidden 8, embedding 4, rank 2, lr 1e-3, wd 1e-4).
  The config with the lowest mean best-validation error wins. Final epochs = max(1, median of per-fold best epochs).
- **Bidirectional runner.** One crossed-CV stage for all 8 variants, with **no architecture grid**. Every variant uses
  hidden 8, embedding 4, rank 2, lr 1e-3, wd 1e-4. CV selects epochs (median best epoch), the legacy aggregation, and
  λ. Early stopping uses the calibrated prediction (λ = 1).

**Frozen recipe → evaluation:** the tune task's selection.json (configs, epochs, aggregation, λ) is frozen
("fixed_global_from_dependency") and reused for:
- 1 full-data fit (random_split: all 10 apps in training, scored on the 45 non-self pairs);
- 70 restricted fits = 10 balanced splits × sizes 2–8, each scored on one-known and zero-shot.

**Splits** (`nested_orders`, BD/run_experiments.py l.134):
- One random permutation of the 10 apps (seed 811); split k is its cyclic rotation by k.
- Training set = the first `size` apps of the rotation, so training sets are nested within a split.
- The s00 order is AMG2023, Laghos, Beatnik, MiniFE, FIESTA, LAMMPS, TriC, Kripke, Quicksilver, miniVite.
- All five runs use identical split membership.

**Task counts:**
- One-way runner: 3 tuning + 1 full-data + 70 restricted = 74 tasks.
- Bidirectional runner: 1 + 1 + 70 = 72 tasks.
- Total: 3 × 74 + 2 × 72 = 366, as in the artifact.

**Seeds:** each final fit trains 5 seeds. The ensemble prediction is the **mean of the latent log predictions** across
seeds, then floored at 0 (BD/pipeline.py l.1487–1505). CV is averaged over seeds within each group.

**Selected recipes** (artifact §2 plus `cv` in the DATA):

|---|---|---|---|---|

| One-way MPI, legacy | rank 4, hidden 16, lr 3e-3, wd 1e-3, 6 epochs, uniform agg. | 10 epochs | 4 epochs | – |
| One-way total time | rank 4, hidden 16, 4 epochs, OOD-kernel agg. | 4 epochs | 6 epochs | – |

## A4. Uncertainty (`BD/metrics.py` l.181–250; the artifact used the same procedure)

**Full-data intervals:**
- Pair clusters are the 45 non-self unordered pairs, each carrying both directional outcomes.
- **One shared draw matrix** (1,000 × 45, `rng.choice` with replacement, seed 923) is used for every method.
- For each draw, every method's metric is recomputed on the resampled rows, and the method's metric minus the
  baseline's is taken.
- The 95% CI is the 2.5% and 97.5% percentiles of those paired differences (percentile bootstrap). Δ% = Δ / baseline
  log MAE.

**Restricted tiers:**
- Per (split, size) cell: method log MAE and baseline log MAE over that cell's outcomes.
- Pooled skill = 1 − mean(method) / mean(baseline) over completed cells.
- Win rate = fraction of cells where method log MAE < baseline log MAE. The artifact's "sd" field is the SD across cells.
- These spreads are **descriptive only**: splits are overlapping rotations and seeds are refits, not independent samples.
- Per-split ratios are undefined when a zero-shot cell has only floor outcomes, which is why the skill is pooled.

**Pair-level false-benign rate at 1.05** (metrics.py l.330–388):
- Numerator: pairs where the worse endpoint truly is ≥ log 1.05 but the predicted worse endpoint is below it.
- Denominator: the truly harmful pairs, which are **29 / 45 (MPI)** and **5 / 45 (total time)**.
